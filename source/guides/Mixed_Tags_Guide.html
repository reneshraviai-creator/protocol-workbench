# Mixed tags, templates and simulation controls — Phase 5

## Generate several datatypes together
1. Open Tags & registers and select a stopped connection.
2. Choose Create tags · Bulk Generate · Mixed Datatypes. Existing Single datatype and Import DB / CSV remain available.
3. Add/remove datatype rows. Set each row's datatype, quantity, prefix, initial/default value and pattern. Open Naming, simulation parameters & group for separator/suffix, starting index/padding, custom naming, pattern parameters, group and activation.
4. Quantity mode sums the row quantities. Percentage mode uses Requested total and row percentages, which must total exactly 100. Largest-remainder rounding assigns remaining tags in stable row order when fractional shares tie, so totals always match.
5. Set conflict policy: cancel rejects the whole plan; skip omits conflicting names/NodeIds; rename adds deterministic _1, _2 suffixes. No policy overwrites existing tags. Address overlaps are always rejected rather than silently skipped or moved.
6. Generate preview. Progress reports processed/requested candidates. Cancel generation discards the result and creates no tags. Review per-row counts/types/defaults/patterns, first/last names and conflict counts. Invalid rows report an error; no partial result can be accepted.
7. Confirm & create tags applies a ready, unchanged preview to the workspace draft. Changing the connection or row specification requires another preview. The preview expires after ten minutes and can be accepted only once. Save project to persist the tags. No device writes occur during generation/preview/creation.

Up to 100 rows and 20,000 configured tags per connection are supported. A preview checks the whole proposed connection, including existing tags. Skipped duplicates can reduce the final quantity. Each created tag has a unique identifier, canonical datatype, initial value, pattern parameters, group and enabled state. The backend yields every 200 candidates and validates the final draft off the event loop. At most two previews run concurrently and eight recent results are kept; oldest finished results can expire/evict. Use Cancel generation before closing a form if you want to stop its preview task; simply closing the form cannot apply tags but can leave its bounded preview work running to completion. Results and progress are temporary process memory, not persistent queued work.

## Datatypes and protocols
- Boolean / BOOL.
- SByte is the canonical OPC UA identifier for SINT / Int8; Byte for USINT / UInt8 / BYTE.
- Int16 / INT, UInt16 / UINT / WORD, Int32 / DINT, UInt32 / UDINT / DWORD, Int64 / LINT, UInt64 / ULINT.
- Float / REAL / Float32; Double / LREAL / Float64.
- String and DateTime: OPC UA client scans, simulation writes and local simulator servers only. They are disabled in the mixed Modbus form and rejected by the backend for Modbus. Numeric gateway transformation of String/DateTime is not supported in this phase.
Aliases do not create duplicate underlying types. Modbus SByte/Byte use one whole register, not packed byte arrays: signed Int8 is sign-extended to signed 16 bits and UInt8 is zero-extended. Decoding rejects values outside the selected 8-bit range. Existing byte/word orders still apply. Always match the other equipment's register convention; packed byte devices need a different mapping.
String values are limited to 4,096 characters. DateTime requires an ISO 8601 timestamp with timezone, such as 2026-01-01T12:00:00+08:00; it is normalized to UTC and must be year 1601 or later. DateTime JSON/evidence uses ISO text. Float32 is rounded to its protocol representation; integer/Boolean values remain exact. Keep Int64/UInt64 values as decimal strings in templates/JSON and spreadsheet imports to avoid JavaScript/spreadsheet precision loss.

For an existing PLC/server, generated tags are client configuration: they do not create PLC DB variables or grant access. Resolve/Browse and validate the server's actual NodeIds/types before writing. OPC UA generated NodeIds can include a namespace and prefix. The existing local simulator creates namespace 2 nodes using the tag name under Objects → Simulation, so use namespace 2 and an empty NodeId prefix for that local-server workflow. Modbus addresses are zero-based; offset 0 is commonly displayed as 40001. Blank row offsets pack whole scalars after existing occupied addresses in that area. Explicit offsets never overwrite existing spans.

## Names and initial values
Default name: {prefix}{separator}{index}{suffix}. Supported placeholders are exactly {prefix}, {separator}, {index}, {suffix}. Index is sequential with optional zero-padding. Generated names are 1–250 characters and naming fields reject control characters. Prefix/suffix/separator fields are literal text. Existing names and NodeIds are checked across all rows and existing tags.
Default value is an initial value applied on the first cycle of a new run. Constant pattern value is a separate parameter controlling later cycles. Set both when you want a fixed value throughout. Recovery after an uncertain client write does not replay the first initial values; Phase 3 recovery policies still apply. Stop then Start is an intentional new run and can apply initial values again.

## Typed patterns and precision
Boolean: constant true/false, toggle, deterministic random Boolean, or custom sequence.
Integers: constant, increment, decrement, random, ramp, step and existing sine/custom sequence. Float/Double support the equivalent numeric patterns.
Increment/decrement use configured minimum/maximum and step, clamp at the bound and restart at the configured period. Integer steps must be whole numbers; UInt64 increments use decimal arithmetic without converting bounds to floating point. Step alternates between minimum and maximum at half the period. Numeric random remains deterministic by seed, wall-clock slot and tag index so independent numeric clients can agree.
String: constant, text_sequence (text prefix + cycle-within-period + suffix), random_text (12 deterministic alphanumeric characters plus affixes), or a custom sequence.
DateTime: current_timestamp (actual UTC time), fixed_timestamp, increment_timestamp (fixed base + step seconds per cycle within period), or a custom sequence. Current timestamps sampled by separate calls are not guaranteed identical.
Custom sequences in the mixed form are JSON arrays, for example [1,2,3], [true,false], ["OPEN","CLOSED"] or ["2026-01-01T00:00:00Z"]. Minimum/maximum, step, period and defaults are validated for the selected datatype. Some parameters do not apply to all patterns. The existing tag table still supports CSV/sequence editing; do not change a String/DateTime tag to an incompatible numeric pattern.
Live numeric patterns use the existing common wall clock, rather than elapsed time since Start. Offline preview uses relative cycles. Pause/resume advances to the current slot; it does not replay every missed slot. Period is 2–1,000,000 cycles. Values must be finite and within the datatype's range. Invalid defaults, patterns or parameters reject the whole mixed plan.

## Reusable templates and simulation profiles
Expand Reusable mixed templates & simulation profiles in the mixed generator. Save new stores the current rows as a reusable local configuration. Select a saved template to Load, Update selected, Duplicate selected or Delete selected (with confirmation). Deleted files are retained in the local mixed-templates/trash directory; there is no in-app trash restore button. Export JSON saves the current configuration, and Import JSON loads a draft for editing/review before generation or Save new. Only version 1 mixed-template JSON is accepted by the form.
Templates include datatype distributions, naming rules, defaults, patterns and groups; they do not include a PLC endpoint, credentials or existing tag IDs. Templates are local to this data directory, up to 200 active templates. They are separate from existing scenario/community templates; no online publication happens automatically. Save validates the entire configuration, including protocol compatibility. Editing or importing a template does not alter running jobs.

## Groups, profiles and selective activation
Tags & registers → Groups & profiles. Choose a group and optionally a saved template row as its simulation profile. Every tag in the group must match that row's canonical datatype. Apply sets the group's per-tag simulation overrides atomically in the workspace draft; Save project persists them. The profile's generation quantity/naming/initial default does not rename tags or reset existing initial values. Use the tag table to edit initial values separately.
Active in jobs controls participation when the next job starts. Inactive tags remain configured but the existing client worker/local server excludes them. Running snapshots do not change when you edit a draft; stop the affected job before changing profiles or activation. A job with no active selected tags stops with an error rather than writing something else. Gateway routes retain their explicit mapping selection; use route mappings rather than group activation for gateways. Group activation is not a permission or safety control and does not prevent an explicit manual operation.

## Start, pause, resume, schedule and duration
Simulation & routes retains Start and Stop and now has Pause/Resume for simulation/server jobs. Pause takes effect at the next cycle boundary; an in-flight operation completes first. PAUSING means that boundary is pending; PAUSED means no further cycles run. Connections/listeners and resource reservations remain held. A local server remains readable while paused. Resume continues the same run using current values. Phase 3 unknown-write holds require their separate recovery review; Pause/Resume cannot bypass those holds.
Configure job → Schedule & duration. Start at accepts a timezone-aware ISO timestamp; blank means immediate. Start explicitly arms the scheduled run and reserves its resources immediately. Past timestamps begin immediately. Stop cancels the schedule. Existing opt-in project autostart can arm schedules at app startup; no new scheduler silently arms stopped jobs. Scenario step timeouts still apply to scheduled starts, so allow for the delay when designing a scenario.
Duration is optional, 0.1–604,800 seconds. It starts before connection/server setup after the schedule delay and includes pauses and recovery waits. At expiry the normal worker is cancelled and cleaned up; state becomes COMPLETED. It does not wait indefinitely for a paused/recovery-held operation. An in-flight external write can still have an unknown result; inspect Communication verification before starting again. Stop retains last destination values, as before.
Job cards show cycles and optional elapsed/progress. Completed workspace simulation/server runs enter bounded process-local history (200 records; latest 50 displayed on the dashboard/routes page). Scenario runs continue using their existing scenario reports rather than the main workspace history. History/progress is observed runtime evidence, not a durable audit log, and clears on restart. Export a project/template for configuration and use existing verification/performance exports for communication evidence. Schedule resources are held until completion/Stop, preventing conflicting writers/listeners.

## Troubleshooting and scope
Preview error: correct the row/datatype/pattern, duplicate name or address overlap, then generate another preview. Existing tags remain unchanged.
Create disabled: no ready preview, a changed configuration or cancelled/expired result; preview again.
Template import error: check version, rows, canonical aliases, percentage total and protocol. Reusable templates cannot grant missing OPC UA permissions or create PLC DB members.
No local OPC UA values: use namespace 2 and no NodeId prefix for the existing local simulator, then check active tags and server status.
Pause rejected: only RUNNING/OVERRUN simulation/server jobs pause. Stop a scheduled run, or use Communication health for a recovery hold. PAUSED jobs still own resources.
Duration ends during setup: increase duration or reduce the server's tag count. Duration includes setup and pause time.
This phase does not implement protocol bridging changes, native installers, online template sharing or physical-hardware certification. Local OPC UA/Modbus and existing virtual RTU regressions are covered; use isolated simulators/test equipment under the existing terms. Installer archives are unchanged.
