# Administrator guide — Preview 11

Installation is per OS user; initial authentication is OFF. Create the first Administrator yourself in Security & access. Passwords must not be shared in chat. Local accounts, roles, sessions, certificate pinning and encrypted credential references are described in Security_Guide.html. Back up the whole stopped data directory, including vault.key, before upgrades. Someone controlling the OS account/files is outside the local application account boundary.

## Paper licence administration
After sign-in and receipt acknowledgement, open Project & settings → About → Licence Information. An authenticated Administrator may update licensed organisation/user, reference, type, issue/optional expiry date, publisher and support contact. Enter only details from the separately maintained agreement; do not invent a reference or imply a draft is executed. Dates use YYYY-MM-DD; expiry cannot precede issue. Stale updates are rejected. Installed software name/version are fixed by the release.
Licence information lives in the existing project-library settings database and survives restart. It is global to the installation, not a role/feature entitlement. Authentication-off users can view but cannot edit it. Expiry never disables operations. Updating metadata does not force repeated notices within an acknowledged session. A new login requires acknowledgement of the current notice. The audit records the account, metadata revision and exact notice hash once per session. Acknowledgement is informational receipt, not an electronic agreement/activation. Safe stop controls remain available before acknowledgement.

## Installation controls
Install stages runtime/import/protocol checks before switching releases. Start/stop/status/validate are explicit. No automatic system service or new login-startup task is installed by packaging. Existing project autostart remains an intentional user setting; authentication mode suppresses it. Upgrade backs up stopped data and retains the previous release. Rollback explicitly rewinds to the previous release and its matching data, retaining current data separately. Read Installation_Guide.html before use.

Validate Installation runs isolated synthetic OPC UA/Modbus checks with no saved endpoints. The authenticated in-app self-test additionally requires review of its fixed loopback-only operation; its ephemeral synthetic targets are not saved device addresses. Create Diagnostics produces a minimal ZIP containing software/runtime/dependency details and presence of known data files. It excludes project contents, accounts, licence parties, tokens, logs, paths and recordings by design. Review even minimal diagnostics before sharing. No upload occurs. Detailed engineering logs must be reviewed/redacted and exported separately through the app.

## Distribution boundaries
Windows ARM64/x86/x64 include local runtimes and third-party notices. macOS/Linux use pinned online requirements. Read RELEASE_STATUS.txt and native acceptance evidence; static PE/checksum verification is not Windows/Linux execution. Packages are unsigned archive installers. Editable documentation and the paper agreement DRAFT are included under guides/editable. The agreement requires counsel review and signature outside the application; this package does not issue it. Protect local configuration and full-data backups. Phase12 independent qualification is outstanding.
