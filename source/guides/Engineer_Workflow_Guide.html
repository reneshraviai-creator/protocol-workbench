Create a simulator and read it locally

  1. Choose Create simulator. Select a device symbol, protocol, endpoint, tag count and update interval.
  2. Choose Continuous until stopped or Timed. Creation saves a stopped device and job.
  3. Open the device and press its Start button. Confirm its displayed endpoint, port or serial settings.
  4. Choose Connect a local scanner. For a workspace simulator this copies its known tag map; it is not a discovery claim for arbitrary Modbus equipment.
  5. Open the scanner and choose Start read-only monitor. Received values are labelled separately from generated server samples.
  6. Use Running now to return to either owner. Use Live values / trends for recording and watchlists.

Modbus RTU requires a real serial interface or existing virtual serial pair, compatible peer settings and suitable wiring. Device artwork represents sample signals; it does not emulate equipment physics.

Use a template without losing your place

  1. Open Tests & templates, then Create test from template.
  2. Enter a test name and every endpoint. Review tags and steps; create the saved test.
  3. The app takes you to that test card. It is stopped. Its endpoints are shown on the card.
  4. Choose Run test. Use Open active run for progress or Find running devices for the independent run endpoints.
  5. The template records links to tests created through this flow. Older imports may lack provenance; names alone are not treated as proof of a relationship.

Remove and restore

Choose Delete template to move the recipe to Trash. Created tests and active runs continue unchanged. Choose Trash / restore to restore it. For a saved test, expand Reuse, history & remove. Stop its active runs first. Removing the definition retains run evidence. Restore never starts traffic.

Device removal is different: open the device's Jobs & dependencies, review linked jobs, scanners and monitors, then stop/remove dependencies as required. Saved tests retain independent copies.

Find a task or diagnose a failure

Choose a task opens guided entry points for simulation, device setup, server import, routing, automation and recording. Engineering tools retain the advanced tag editors, verification, health, performance and reports. Context links return to the selected workspace device. Evidence pages may show the entire workspace; their filters and labels define the scope.

Running now includes all active runs, even when newer completed runs exceed the history limit. ERROR rows need attention. A running listener is not proof that another device is communicating. Do not use this build for production control.
