Projects & configuration management

Workspace versus library

The Workspace is the single editable/runnable configuration used by Connections, Tags & registers and Simulation & routes. The new Projects library keeps named configurations alongside it. Saving the workspace does not automatically update a library project. Capture or Update from workspace explicitly. Library operations do not perform protocol traffic.

Capture your existing setup

1. Save workspace changes using Save project.

2. Open Projects → Capture saved workspace.

3. Give it a name and description. Optionally include all currently saved scenario definitions as independent copies (up to 100). Runs, reports, watchlists, recordings, accounts and secret values are not captured.

4. Click Capture project. Your workspace and running jobs remain unchanged.

Create, open and edit projects

New empty project creates a library entry using the currently configured creation defaults. It does not replace the workspace. Before opening any project, capture or export your current workspace. Stop all jobs, scenario runs, monitors and client data operations. Click Open, review the selected configuration, check the confirmation and choose Open stopped configuration. The backend rechecks activity under the engine lock and requires the exact current workspace revision. A stale window is rejected. Loading disables autostart and starts no jobs. Existing saved scenarios remain in their independent catalogue.

Use the existing Connections, Tags & registers, Simulation & routes and Project & settings editors to change the opened workspace. Save project, return to Projects and select Update from workspace on the intended library entry. This appends a revision while preserving its captured test definitions. This is an explicit copy workflow, not a live-linked project tab system. Check the entry name before updating; updating adopts the workspace's name. Details & history edits the project name/description and appends a revision. Duplicate creates an independent entry with new history. Library list order places most recently opened projects first, then recently updated projects.

Revisions, archive and recovery

Details & history shows numbered revisions, reasons, timestamps and the current content SHA-256. Restore as new revision appends an older configuration as a new head; it does not overwrite historical revisions or apply to the workspace. Open separately after review. Historical metadata displays the current library entry's label, while each revision retains its own configuration name. Archive requires typing the exact project name and checking its current revision on the backend. It hides the project from the active list but retains its contents/history. Show archive → Restore project reverses this action. There is no permanent project purge in this phase. An open workspace is an independent copy and remains unchanged by archiving.

Backup, import and migration

Backup JSON exports the current project configuration and captured scenario definitions as protocol-workbench-project version 1, with a canonical SHA-256 integrity checksum. It does not include the complete local revision history or other app data. Password/token fields and certificate/private-key/server-certificate paths are omitted. Endpoint addresses, usernames, tag names, register maps, values, expressions and free text may remain sensitive; review before sharing.

Import / restore backup accepts a verified package or a legacy version-1 workspace JSON. Preview shows the migration result and configuration counts. Import creates a NEW library entry; it never overwrites the workspace or an existing entry. Legacy workspace JSON is wrapped into the library schema, validated and has autostart disabled. Unknown formats/schema versions and invalid checksums are rejected. There is no arbitrary migration script execution, automatic field guessing, or downgrade of security policies. File size is constrained by the application's request limit and the library's 20 MiB content limit.

After opening, passwords can be reused only from a matching currently saved connection identity (the existing recovery identity checks apply). Otherwise re-enter them in Connections. Imported secure configurations also require locally valid certificate/key paths. Do not assume a backup contains working credentials. A checksum detects accidental changes; it is not a digital signature or proof that a supplied project is trustworthy. Review all destinations before running.

For a full installation backup, stop the app and back up the entire data directory, including project.json, scenarios.sqlite3, project-library.sqlite3, recovery, reports, security databases/key and certificate files. Restore the complete directory with the matching application version while stopped. Protect credentials and private files separately; the portable project backup is not a complete installation backup.

Connection, tag, simulation and test configuration

Save workspace connection as profile copies a saved endpoint plus its tag map into the local profile library without passwords. Add copy to workspace draft gives the connection and its tags fresh IDs. Review credentials, endpoint, addresses and types, then Save project. Existing jobs/mappings are not redirected. Profiles are separate reusable copies and do not track later device edits automatically. Profile listing and creation/copy are provided in the GUI; the backend also supports explicitly confirmed removal.

Tags and simulation settings use the existing bulk editors/generators, per-tag patterns, mixed templates and job editors. They are preserved in project revisions and JSON backups. Restoring a saved test definition through Details & history → Copy to Scenarios creates a new ID and a stopped test; it does not overwrite or execute an existing scenario. Edit and validate that copy in Scenarios. To capture revised scenario definitions, capture a new project with the desired saved scenarios included. Update from workspace intentionally retains the project's existing test-definition snapshot.

Defaults, preferences and application settings

Defaults for new projects controls advanced new-job simulation interval, standard new-connection timeout/reconnect delay and generated tag prefix/count. These defaults are copied into empty library projects created afterward; older configurations remain unchanged. Guided wizards retain their own reviewed workflow settings. Open the new project to use its defaults in the existing advanced editors. My preferences saves landing page and comfortable/compact table density per authenticated username. With authentication off, these preferences belong to the shared local account. They apply on next login/reload (density changes immediately). Existing Project & settings, Security & access and performance/logging settings remain their own controls; this phase does not reset them. When authentication is on, Administrator and Engineer may manage configurations; Operator and Read-only may view the library and exports but cannot change/open projects. Every role may change its own display preferences. Only Administrator may change global new-project defaults. Authentication-off retains the existing unrestricted local workflow.

Validation, limits and troubleshooting

All projects/scenarios pass existing configuration validation. Reads verify canonical content checksums; updates require the current revision and refuse a corrupt current head. Imports validate before inserting. Library schema upgrades currently support new/schema-1 storage and legacy workspace version 1 import; newer unsupported database versions fail closed. No running protocol snapshot is rewritten by library editing. Limits: 100 projects INCLUDING archived projects; 50 retained revisions per project; 100 profiles; 100 captured tests per project; 20 MiB per configuration/profile and 200 MiB total logical revision/profile content. History is not silently pruned. At 50 revisions, duplicate the project to start fresh history. Physical SQLite allocation can exceed logical content limits. Metadata/preference storage is not a general user-controlled file store.

- Stop jobs error: stop all workspace jobs, runs, monitors and active client data operations before opening. Capture/update/duplicate remain available while jobs run.

- Revision changed: refresh, inspect the latest revision, then repeat deliberately. Do not bypass stale-write checks.

- Integrity check failed: do not edit the database to suppress the check. Import a known verified backup into a new project or restore a complete stopped-app data backup.

- No project appears after saving: workspace Save project and library Capture/Update are deliberately separate actions.

- No test appears in Scenarios: captured tests are stored within the library project; copy the desired test explicitly.

- Invalid defaults or unsupported schema: correct the configuration; unknown versions are not guessed.

Main protocol adapters, security, scenario execution and UI remain unchanged in scope. This release is an Engineering Preview. Native OS installers, upgrade/rollback qualification, physical PLC/RTU acceptance and independent endurance testing remain later work. Phase 11 has not started.
