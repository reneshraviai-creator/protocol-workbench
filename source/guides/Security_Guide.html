Security & local access — Phase 9 preview

Start safely

This application is intended for local simulators and isolated test equipment. Security mode is optional and is initially OFF for compatibility. OFF means the existing loopback/Origin/CSRF token checks remain; it does not provide individual accounts, role restrictions or new write leases. No administrator password has been created in your main workspace.

1. Open the application, then Security & access.

2. Stop all workspace jobs, scenario runs and monitors. Export any unsaved work you need.

3. Click Enable local authentication. Choose a username (3–64 letters/digits/dot/underscore/dash) and a password (12–128 characters). Check the enable box and submit yourself.

4. Sign in. The first account is Administrator. Use Add / update account to create other users.

5. Choose a role deliberately. Enter the exact existing username to change its role, enabled status or password. Leave the password blank to keep it. Changes revoke that account's sessions. The last active Administrator cannot be demoted or disabled.

6. Set Session timeout, 1–240 minutes. Default: 30 minutes since the last API command; background GET polling does not prolong it. A session has an absolute 24-hour lifetime. Restarting ends all sessions.

Roles and backend enforcement

RoleCapabilities
AdministratorAll existing API operations, accounts, security settings, logging policy, startup and shutdown.
EngineerConfigure workspaces, tags, scenarios, templates, certificates and reports; read/test endpoints; start operations; manually write after confirmation. Cannot manage users/security settings, startup/shutdown or logging policy.
OperatorStart/pause/resume/stop existing saved jobs and scenarios; start saved-device monitors/watchlists and recordings. Cannot change saved configurations or perform ad-hoc manual writes.
Read-onlyView saved configurations, existing monitors, evidence and reports; test/browse/read endpoints through the connection API. Cannot save configuration, start jobs/runs, create monitors or write.

Every signed-in role can safely stop all jobs/runs/monitors, stop an individual owner and pause a job. There is no unauthenticated HTTP stop bypass. The trusted local OS owner can stop the application with its launcher. Primary configuration/start controls are disabled for restricted roles; other forms may still be visible and receive a backend permission error. A new mutation endpoint is denied to non-administrators until explicitly allowed.

Writes require review

When authentication is ON, starting a writer opens Review & enable writes. Check the endpoint, unit, nodes/registers (first 100 shown), physical address count and isolated equipment before consenting. Cancel sends no write/start operation. Consent is bound to the exact request and authoritative saved configuration, including scenario contents. A changed endpoint, tags, values or configuration needs a new review. Review expires after 60 seconds; accepted consent must be used within 30 seconds and is consumed once.

A worker's write lease lasts five minutes. Adapter calls are limited to 10,000 tags and the planned operation to 20,000 physical addresses (a Float uses two Modbus registers). Server simulations also have a 10,000-point cap in authenticated mode. Split larger operations. Sign-out, account changes, session expiry and lease expiry cancel owned writer tasks. The cancellation sweep runs every 250 ms; adapters also check before batches and dynamic servers before cycles. Already transmitted/in-flight operations cannot be recalled. No rollback or physical safety guarantee is implied. Expired writers must be stopped and started again; resume does not extend the old lease. Long running legacy simulations remain available with authentication OFF, with the stated legacy limitations. Authentication mode disables automatic job startup.

OPC UA credentials and certificates

Authenticated mode requires SignAndEncrypt for username/password use. Anonymous Security=None remains available for isolated labs. Modbus TCP/RTU is inherently unencrypted here; these controls do not add transport security to Modbus.

Enter protocol passwords in the existing connection form. Saving a configuration in authenticated mode stores an opaque secret: reference; the encrypted value lives in security/vault.sqlite3. References are bound to the exact endpoint URL, username and security mode. Changing one requires re-entering the password. Do not copy references to a different workspace. API configuration/recovery reads replace legacy plaintext passwords with references without silently rewriting the original saved project; saving explicitly migrates the selected configuration. Old recovery history, recordings, logs and backups are NOT retroactively sanitized. Protect them separately.

Upload client certificate, matching private key and explicitly trusted server certificate through connection settings. PEM/DER certificate and key contents are validated. Private keys must currently be unencrypted PEM/DER files; local file protection is the boundary. The secure adapter checks matching client key, client validity and URI SAN, pinned server fingerprint, server dates, application URI, key usage, server EKU and exact DNS/IP SAN. Client application URI is taken from its single URI SAN (or a matching application_uri advanced configuration field). Wildcard DNS SAN matching is not implemented. No automatic certificate trust, CA chain building, CRL/OCSP service or certificate issuance is provided. Certificate inventory shows managed public certificate fingerprints/dates, never private key contents. Manage the server's trust of your client certificate in the server's own tools.

Audit history

Click View security audit history. Reports & diagnostics opens with Category=security. Sign-in success/failure/throttling, account/settings changes, denied permissions, write approvals/starts, writer cancellation and authenticated API mutation outcomes are recorded. Configuration changes are recorded as path/account/status events; existing recovery history holds configuration versions. The shared communication ledger records per-point write responses. Logs are bounded and may rotate; export evidence needed for acceptance. Logs are not immutable or tamper-proof, and logging failures do not stop protocol work. Never treat these events as a complete device-side audit.

Storage, backup and recovery

Back up the ENTIRE data directory while stopped, including security/users.sqlite3, security/vault.sqlite3, security/vault.key, configurations and certificates. The vault uses Fernet encryption; the decryption key is beside the encrypted database under the user's private data folder. This protects against accidental plaintext disclosure, not a compromised OS account or someone who can read both files. POSIX private directories/files use 0700/0600; Windows depends on the user's data-directory ACLs and still needs native acceptance testing. No keychain/HSM integration is claimed.

If an administrator forgets its password, stop the app. From the installation folder, using its Python interpreter, run:

python app/security_recovery.py --data "FULL PATH TO YOUR DATA FOLDER" --username YOUR_EXISTING_ADMIN_USERNAME

The utility verifies that the app is stopped, prompts locally twice with hidden input, and resets an existing Administrator only. It never disables authentication. It requires the same trusted OS account/filesystem privileges; do not share passwords in chat. If the vault key is lost, stored protocol passwords cannot be recovered: restore the matching backup or enter fresh credentials. Do not delete the security folder to troubleshoot.

Troubleshooting and limits

- Sign in to continue: session expired/revoked or app restarted. Sign in; never assume an interrupted write succeeded.

- Your role does not allow this operation: ask the administrator to review the role. Editing browser controls does not grant access.

- Stored credential belongs to another endpoint: enter the password again for the changed endpoint/user/policy.

- Certificate does not identify the endpoint: use the matching DNS name/IP or reissue the certificate with the correct SAN. Do not bypass validation.

- Write authorization expired: stop/restart and review targets again. Inspect communication evidence for in-flight UNKNOWN outcomes.

- Too many login attempts: wait a minute. Five attempts per username/minute, bounded to 200 distinct entries; at most 100 active local sessions, 50 accounts.

This is a loopback HTTP development preview. Cookies are HttpOnly/SameSite=Strict, but HTTP does not provide TLS/Secure-cookie transport. Never expose the port through forwarding/reverse proxies. No independent penetration test, Windows/Linux hardware acceptance, production qualification or installer rebuild is claimed. Existing source history has private checkpoints and must not be published without sanitization. Scrypt settings N=131072, r=8, p=1 follow the minimum configuration in the OWASP Password Storage Cheat Sheet. OS owners can access process memory/files and are outside the account isolation boundary.
