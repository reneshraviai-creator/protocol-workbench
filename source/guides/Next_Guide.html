Choose a task on the Dashboard

Monitor a device reads device values; Simulate a device opens a guided setup; Connect two protocols pairs source/destination tags; Run a test opens saved scenarios. Tasks explain missing device/tag prerequisites. Advanced monitor settings are collapsed by default.

For a protocol route, choose two saved devices with tags, then match exact names or choose one pair by typing the exact tag names. Review the count and preview. Optional timing, multiplier and offset settings are under Advanced. Create the stopped route, then inspect all pairs using Mappings before starting. A destination simulator must have dynamic updates disabled if the route will write those same points. Form submission errors appear inside the dialog.

Add your first device

  1. Choose Add device · guided. Enter a name, protocol and endpoint. Security/timeouts are under Advanced.
  2. Use Test connection, or continue with an offline configuration. A Modbus TCP connection alone does not verify register addresses or unit ID.
  3. Browse OPC UA scalar tags, import CSV/Siemens DB definitions, or generate numbered tags. Review and select definitions; this does not create PLC variables.
  4. For Modbus, explicitly choose reference or zero-based notation. 40001 → holding offset 0. Check a sample value’s raw-word representation against the device manual. CSV addresses remain zero-based.
  5. Read a sample of up to ten selected tags. Check decoded values, quality, source timestamps or raw words. You can save offline without reading.
  6. Review and save. Existing configuration is preserved. Choose monitoring, simulation or route setup as a next step; nothing starts automatically.

Browse metadata covers the first 5,000 returned variables; unsupported/inaccessible types are reported as skipped. Generated/imported definitions can cover larger sets. Conventional five-digit Modbus reference notation is supported; use zero-based offsets for extended maps. Unfinished wizard edits can be resumed through Recover work after draft protection completes.

Your first automated protocol test

  1. Open Scenarios and click Try local Modbus example.
  2. Click Run test. The example uses a loopback server on port 15030; it does not connect to your PLC.
  3. Open Test runs → View results. Inspect the written value, readback and expected tolerance.
  4. Click Download HTML report to save the evidence.
  5. Return to Scenarios. Click Edit to add, change or reorder steps; click Duplicate for another test variation.

Live inspector: OPC UA and Modbus TCP

  1. Add/import a connection and tags, then save the project. Start the source simulator separately if needed.
  2. Open Live inspector → Open live monitor.
  3. Choose the device and points. Configure OPC UA publishing/sampling/queue settings or the Modbus poll interval.
  4. Click Start monitoring. This opens a read-only connection; it does not write or start the server.
  5. Use Trend for a live graph and Attributes for OPC UA metadata/references.
  6. For Modbus, expand Modbus traffic to inspect decoded PDUs, raw TCP chunks, exception responses and timing.

Quality, source/receive timestamps and retained last-good values are shown. A constant OPC UA signal can be healthy without new notifications; session health is checked separately. Reconnect retains the last observed values and marks disconnected state. Invalid metadata/access causes ERROR.

Stop monitor leaves source jobs running. Stop all stops monitors, jobs and tests. Export current values as CSV or Modbus traffic as JSON. Trend history is bounded in memory (2–300 received updates per point, depending on group size) and clears on app restart. Separate bounded CSV recording is available below. Up to eight concurrent monitors are supported. Strings/arrays/structures, deadbands, serial transport and historical charting remain future work.

For a local example, choose Load local protocol lab, explicitly accept workspace replacement if needed, start both server jobs, and monitor each device. The sample uses loopback ports 15450 (OPC UA) and 15060 (Modbus), not your PLC.

Guided simulation setup

Click Create simulation at the top. Follow Choose → Connect → Tags → Values → Review. Choose OPC UA or Modbus TCP and either a local server or an existing device. Reuse a configured connection for secure endpoints or real PLC tag definitions; local simulations can reuse a connection as a tag template.

Choose the tag count/naming or existing tag set. Set the pattern, range, interval and duration. Local wizard endpoints are loopback-only. Initial values and units can be assigned to new tags. Reused per-tag overrides take precedence over job defaults.

Save scenario stores configuration without connecting or replacing the workspace. Save and run starts the selected job. The scenario stops its own job after the configured duration and a final read. The final read checks readability/quality, not an expected process response; add assertions for that. Preview and validation are offline. For continuous running, explicitly open the saved scenario in the workspace and start its job there; stop it manually when finished.

The wizard supports intervals from 0.1 to 60 seconds and durations from 1 to 3600 seconds after readiness. Setup and final-read time are additional. Existing-device mode writes exposed tags/registers and retains the last values when stopped. It does not create PLC program variables. Use advanced editors for more detailed settings.

Create your own tags

Open Tags & registers, choose a connection, then click Generate tags. Enter the tag count, prefix/suffix, first number, padding and datatype. For example, Point_ + first number 1 + four digits + count 1000 creates Point_0001 through Point_1000. Float is a 32-bit REAL.

Modbus supports automatic register spacing, area and byte/word order. OPC UA supports namespace and string NodeId settings; local simulator servers use namespace 2 and the tag name, so keep the defaults for local simulation. Click Check & preview → Create tags → Save project. Use Add one tag for a single custom name. Existing tags remain; collisions are rejected. For a connected PLC, these are client definitions: expose the variables in the PLC separately and resolve their real NodeIds.

Create a custom test

Configure connections, tags and jobs in the workspace first. Create a scenario to capture that configuration. Add read/write steps, save a read under a variable name, then add an assertion using that variable. Start-job steps wait for readiness. All test-owned jobs stop when the run ends.

Edit per-tag simulation settings

Go to Tags & registers → Edit table & simulation. Set each tag's datatype, units label, initial value, pattern, range, constant, period (cycles), random seed or comma-separated playback sequence. Blank simulation fields inherit the job settings. Initial values apply on the first cycle of a new run. Units are display labels.

Search and select tags, then expand Bulk changes to selected tags. Copy/paste rows using the tab-separated header provided; this updates existing names only. Undo edit reverses draft edits; Undo tag edit outside the editor reverses an applied batch in this browser session. It will not overwrite newer unrelated changes. Save the project after applying or undoing.

Preview values shows twelve offline cycles for up to ten selected/filtered tags, with the chosen job defaults. It does not connect or write. Live waveform phase is based on the shared clock. For Modbus, optional register repacking accommodates wider datatypes; use it only for a map you control. A mixed Float/Boolean/Int32 example is provided in examples/Mixed_Per_Tag_Simulation.json. Project JSON export preserves all settings; older tag CSV export does not include every override.

Bulk read, write and verification

Choose Try 20-point bulk test for a ready-to-run example. In a read/write step, choose Tags to use → One tag, Selected tags, or All tags on this connection. Selected tags supports search, checkboxes, select matching and pagination. A bulk write uses one common value for all selected points; it must be valid for every selected datatype. A bulk read saves all values under one variable name. An assertion against that variable checks each tag individually.

In View results, click the tag results button beside a step. Search, filter pass/fail outcomes, and export all tag evidence to CSV. HTML reports include every tag. Interrupted operations can have an UNKNOWN device outcome; completed earlier batches remain recorded. Bulk operations are not atomic.

Results

PASSED: all steps succeeded. FAILED: an assertion did not match. ERROR: connection, timeout or execution failure. CANCELLED: stopped by request. Remaining steps are counted as skipped.

Share and reuse simulation templates

  1. Open Scenarios and choose Save as template to add a saved scenario to the local library, or Export template to download a portable JSON file.
  2. Review the export notice. Passwords, usernames, certificate paths and endpoints are excluded. Tag names, NodeIds, descriptions, values and register maps remain; review these before sharing.
  3. Under Local template library, choose Import template file, or use Create scenario on an existing library card.
  4. Review counts and steps. Enter every device endpoint, and Modbus TCP port where applicable. Choose a new scenario name.
  5. Click Create scenario. This creates a new stopped scenario and preserves the workspace and existing runs. Review destinations before clicking Run test.

Templates retain security policies but exclude local authentication/certificate files. Configure those using the workspace connection editor and capture a new scenario before secure use. Imported NodeIds may need adaptation to the destination server. Preview is offline and does not verify reachability. Local templates persist across app restarts. Hosted community publishing, template version history and signatures are future work.

Saved watchlists and signal comparison

  1. In a running monitor, click Trend beside up to six signals. Remove one with the legend ×.
  2. Choose retained history or a 30-second, 2-minute or 5-minute window. Shared scale uses original values; normalized scale shows each signal relative to its own visible range. Freeze chart pauses the plot only.
  3. Click Save watchlist and name the selection. Reopen it from the left pane after restarting the app. Servers must be started separately. Changed endpoints or selected tag definitions require a new reviewed watchlist. Credentials are taken from the saved workspace.
  4. Use Export trend CSV for all retained selected-signal samples, not just the visible time window.

Capture local CSV evidence

  1. Click Record to CSV and choose a cap of 100–100,000 received tag updates.
  2. Stop recording explicitly, stop the monitor, or allow the cap to close it. Acquisition can continue after recording stops.
  3. Download files from the left recording archive (latest 12). Files persist in the app data recordings folder across restarts.

Recording follows received events, not a fixed sample rate; 1,000 tags can fill 100,000 rows in 100 updates. Quality and timestamps are included. Unexpected exits can lose recent buffered rows; interrupted files are labelled and not replayed. Disk errors stop recording while monitoring continues. Trend buffers remain bounded and are separate from recorded files. Cursor/drag zoom, archive retention tools and a full historian are future work.

Protect and recover your work

The status strip shows Draft, Saved and Running separately. Workspace undo/redo changes the editable draft only; Save project applies it after active-resource validation. Most configuration editors and both setup wizards protect drafts after about 700 ms. Wait for Draft protected before closing. Pending/failed writes warn on browser exit where supported.

  1. Choose Recover work to find unfinished drafts and prior saved workspace/scenario snapshots.
  2. Choose Review → Open as draft. Nothing starts or applies automatically.
  3. Review endpoints and definitions, re-enter omitted credentials if needed, then save explicitly.

Device checks must be repeated after recovery. Simulation review resumes at a configuration step for revalidation. Saved workspace snapshots can restore deleted devices/jobs/tags as part of the whole workspace. Dismissed drafts remain recoverable within retention limits. History retains 10 snapshots per entity, 100 total; drafts retain the newest 30, with size budgets. Export projects separately for backups. Mapping/quick-route/manual-write/monitor/template-preview forms are not draft-enabled yet.

If another window saved a newer project, your stale save is rejected. Wait for draft protection, reload, then review your draft against the latest workspace. Windows, Linux and macOS native acceptance remains part of release qualification.

Verify OPC UA → Modbus signal paths

  1. Use Verify a signal path on the Dashboard. Choose source/observation devices and exact tag names.
  2. Enter a distinct probe and maximum allowed delay. Configure scale, offset, tolerance and polling to match your PLC/gateway.
  3. Review the typed expected value and Modbus words, then save the stopped scenario.
  4. Choose Run test and review destinations. Running writes the probe once and leaves it there; it does not configure your PLC or reset the value afterward.
  5. Open View results for timing/raw-word evidence, or download HTML/CSV reports.

The test refuses an already-matching starting value, blocks bad source quality and reports unknown write outcomes when interrupted. Timing includes protocol and polling delays; it is not PLC-internal latency. Use controlled test conditions. Each step verifies one signal with linear conversion. For a PLC-free example use Try local signal-path example in Scenarios; it starts/stops only its own loopback servers and gateway.

Limits

Up to eight independent scenarios can run alongside workspace jobs. Test runs shows resource owners; use Stop this run to stop one independently. Listener-port conflicts and overlapping write targets are rejected. Resources remain reserved through the full run and cleanup. Unrelated workspace connections/jobs remain editable; active workspace jobs and their connections are protected. Ownership checks apply within this app, not to external software; use consistent endpoint/NodeId definitions because DNS/NAT aliases cannot always be detected. Existing scenario device configurations cannot yet be edited in the scenario editor; make a new scenario from the workspace to capture a different configuration. Reports exclude connection settings. The private local database can contain credentials. Serial Modbus, charts, expanded UA capabilities and advanced automation are subsequent stages.

Stop all ends current jobs and tests. Written device values are retained. Windows, Linux and macOS installers and native acceptance are part of the release plan; this preview is not the final cross-platform release.
